# 开发与运维指南

## 1. 环境要求

- Windows、macOS 或 Linux 上可用的 Flutter；Dart 版本满足 `^3.12.2`。
- Android SDK 和至少一个 Android 设备或模拟器。
- Worker 开发需要 Node.js、npm；部署需要 Cloudflare 账户和 Wrangler 登录。
- 本项目只包含 Android 平台工程。

当前项目最初在 Flutter 3.44.9、Dart 3.12.2、Java 17、Android SDK 36 上初始化。它们是已知可用组合，不表示必须固定所有补丁版本。

## 2. Flutter 客户端

```powershell
cd "E:\workplace1\English word app\Recall_app"
flutter pub get
flutter analyze
flutter test
flutter run
```

构建 Debug APK：

```powershell
flutter build apk --debug
```

默认产物位于 `build/app/outputs/flutter-apk/app-debug.apk`。生产入口 `lib/main.dart` 会使用 SQLite、正式词库和远程文章生成器；测试可通过 `RecallApp` 的构造参数注入内存实现。

若中国大陆网络访问 pub.dev 或 Flutter 存储较慢，可仅在当前终端设置镜像，不要写死到项目源码：

```powershell
$env:PUB_HOSTED_URL = "https://pub.flutter-io.cn"
$env:FLUTTER_STORAGE_BASE_URL = "https://storage.flutter-io.cn"
```

## 3. Worker 本地开发

```powershell
cd backend/recall_ai_worker
npm install
Copy-Item .dev.vars.example .dev.vars
npx wrangler dev
```

`.dev.vars` 仅供本机使用，已被 `.gitignore` 排除。推荐两种配置：

本地 UI 与自动化联调使用 Fake Provider：

```dotenv
AI_PROVIDER=fake
AI_MODEL=fake-context-v1
RECALL_APP_TOKEN=local-integration-token
DEEPSEEK_API_KEY=unused
```

真实 DeepSeek 联调使用：

```dotenv
AI_PROVIDER=deepseek
AI_MODEL=deepseek-v4-flash
RECALL_APP_TOKEN=<独立的本地 Recall Token>
DEEPSEEK_API_KEY=<DeepSeek Key>
```

启动后检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8787/health
npm run typecheck
npm test
```

完整的 Flutter → 本地 Worker → Fake Provider → 客户端缓存联调：先保持 Wrangler 在 `127.0.0.1:8787` 运行，再从项目根目录执行：

```powershell
flutter test tool/local_fake_integration.dart
```

该测试固定使用 `local-integration-token`，必须与 Fake `.dev.vars` 一致。

## 4. App 中的 AI 配置

在首页菜单进入“AI 服务设置”，填写：

- 后端 URL：Worker 根地址，不包含 `/v1/context-article`。
- Access Token：与 Worker 的 `RECALL_APP_TOKEN` 相同。

URL 存在普通首选项，Token 存在平台安全存储。不要把 DeepSeek Key 填入 App。

Android 真机访问电脑上的本地 Worker 时，`127.0.0.1` 指向设备自身。可使用 `adb reverse tcp:8787 tcp:8787`，或让 Wrangler 监听局域网地址并使用电脑 IP；开放局域网监听前应确认防火墙和网络可信。

## 5. Cloudflare 部署

`wrangler.toml` 已配置生产 Provider 和模型，但两个密钥必须通过交互式 Secret 设置：

```powershell
cd backend/recall_ai_worker
npx wrangler login
npx wrangler secret put DEEPSEEK_API_KEY
npx wrangler secret put RECALL_APP_TOKEN
npm run typecheck
npm test
npx wrangler deploy
```

两个 Secret 必须不同。部署后先调用 `/health`，再将 HTTPS 根地址和 Recall Token 写入 App。轮换 `RECALL_APP_TOKEN` 后，所有客户端都需要更新；轮换 Provider Key 不影响客户端配置。

## 6. 变更检查清单

客户端变更：

```powershell
flutter analyze
flutter test
```

Worker 变更：

```powershell
cd backend/recall_ai_worker
npm run typecheck
npm test
```

涉及 SQLite 时，应增加“旧版本数据库升级后数据仍存在”的测试；涉及调度规则时，应覆盖跨日、逾期和反应时间边界；涉及 API 时，应同步更新 Worker、Flutter 防御性校验及[数据模型与 API](数据模型与API.md)。

## 7. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 启动显示词库 SHA-256 不匹配 | Asset 是否被改写；如确需换词库，同时审查内容并更新固定哈希 |
| AI 显示未配置 | App 中 URL/Token 是否为空，URL 是否为合法 HTTP(S) 根地址 |
| Worker 返回 401 | App Token 与 `RECALL_APP_TOKEN` 是否完全一致 |
| Worker 返回 `provider_not_configured` | `AI_PROVIDER`、`AI_MODEL` 是否存在且 Provider 已注册 |
| Worker 返回 `invalid_model_output` | 模型输出是否满足标题、正文、`usedWordIds` 和完整词匹配约束 |
| 文章重复请求 | `contextSessionId` 是否稳定，成功记录是否已写入 `context_articles` |
| 当天任务数高于下调后的目标 | 下调只移除未开始任务；已进入第一层或已完成任务会保留，数量可高于新目标 |
