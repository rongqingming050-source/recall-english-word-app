# Recall_app 正式词库接入与每日任务系统实施指令（修订版）

> 历史文档：本文记录当时的实施要求，不代表全部现行行为。当前设计请从[技术文档索引](README.md)进入。

## 1. 本阶段目标与边界

接入正式考研词库，建立离线、可持久化、可跨天恢复的每日新词任务，并把到期复习与每日新词串成首页学习入口。

允许修改 UI、数据模型、仓储、数据库迁移及学习流程接线；禁止改变第一层三遍规则、高难词规则、第二层 5 秒规则、normal/slow、1/3/7/15/30/60/120 间隔、40% 保守增长、review_attempts 语义及首次 3/2/1 天调度。

## 2. 正式数据源

- `蒸馏/output/final_cleanup_changes.json` 是最后一轮 205 条释义清洗变更清单。
- 这些变更已由 `scripts/final_residual_cleanup.py` 应用到完整词库。
- 唯一可直接打包的完整最终文件是 `蒸馏/output/kaoyan_clean.json`。
- 完整词数固定为 5847，SHA-256 固定为 `d3a817ddb2d272a22ce51269096f65108b4e360ddeaec5352318dfff182646d1`。
- App asset 必须是上述完整文件的逐字节副本。启动时校验 SHA-256 和完整 JSON 结构，异常时明确失败，不得跳过记录。
- 不联网补词，不修改人工确认内容，不把 cleanup changes 当作 205 词的正式词库。

## 3. 正式词条和稳定 ID

正式词库只读，用户学习状态单独持久化。

`WordEntry` 保留：源 ID、position、word、phonetic、meaning、example。正式学习记录使用：

```text
word_id = kaoyan_v1:<源文件 id>
```

源 ID 原样保留；`word.trim().toLowerCase()` 只用于验证源 ID 和查询，不再单独充当正式数据库主键。未来词库更新不得改变已有命名空间和源 ID。测试 Fixture 和旧记录不得使用正式命名空间。

## 4. 数据完整性

导入必须一次性验证：根结构、schemaVersion、元数据字段、expectedWordCount、六个词条字段、position 从 1 连续到 5847、源 ID 唯一、word 唯一、word/phonetic/meaning/example 非空，以及固定 SHA-256。

任一记录异常必须抛出带位置和原因的错误；不得过滤、容错丢弃或用空值补齐。

## 5. 每日设置和日期

- 默认每日新词为 10，集中定义；预设 10、20、30、50，允许自定义 1～200。
- 设置保存在本地 SQLite；修改设置只影响下一个尚未生成的日期。
- 已生成的当日批次不得扩充、缩减或换词。
- 日期采用设备本地日历日，统一持久化为 `YYYY-MM-DD`；业务时间通过可注入时钟获得，不散落调用 `DateTime.now()`。

## 6. 每日任务状态

每个日期先创建不可变批次快照，再创建单词任务。批次即使分配 0 个词也必须存在，以保证同日幂等。

任务至少记录：任务日期、word_id、创建时间、第一层完成状态、语境强化完成状态及对应完成时间。

- 单词被写入每日任务后，永远不能再次作为新词分配。
- 第一层三遍流程完成后标记 `first_layer_completed`。
- 阅读完成、首次复习安排成功后才标记整个每日单词任务 `completed`。
- 第一层完成但语境未完成时，重启后直接恢复语境，不重新进入第一层。
- 第一层进行中退出时，已经独立完成第一层的词立即持久化；剩余词仍属于原任务，不生成新批次。

批次生成和任务插入必须在同一 SQLite 事务内完成，并由日期主键和全局唯一 word_id 约束保证重复调用安全。

## 7. 跨天规则

历史积压指所有早于今天且未完成的任务，不只限于昨天。

```text
历史待完成数 = count(task_date < today && !completed)
今日新增容量 = max(0, 每日目标 - 历史待完成数)
今日新增数 = min(今日新增容量, 剩余从未分配词数)
```

历史任务保留原日期，按日期和任务 ID 从早到晚完成。历史积压达到或超过目标时，今天创建空批次且不新增词。首页分别显示历史待完成数、今日新分配数和总待完成新词数。

## 8. 学习顺序

首页加载顺序：正式到期复习 → 读取或创建当日新词批次 → 显示任务。

点击“开始今日学习”后：

1. 有正式词库到期复习时先复习；
2. 复习清空后自动进入新词；
3. 有未完成语境强化时先恢复语境；
4. 再学习尚未完成第一层的新词；
5. 第一层完成后进入既有语境强化；
6. 两类任务均为 0 时首页显示“今日任务已完成”。

## 9. 旧数据兼容

数据库升级必须使用正式 migration，不删除或重建用户数据库。保留 learning_records、review_tasks、review_attempts 的全部旧数据。

没有 `kaoyan_v1:` 前缀的旧记录视为 legacy：继续出现在 Debug 和 JSON 导出中，但未经人工确认不映射到正式词库、不计入正式词库进度、不进入正式学习入口。不得自动删除或仅凭拼写转换旧记录。

## 10. 页面、Debug 和导出

- 首页显示待复习、待完成新词、历史积压、今日新分配、每日目标和正式词库进度。
- 单词书图标进入“词库信息页”，显示名称、总数、已进入生命周期、未学习和第一层完成数；V1 不建设多词库管理。
- 设置页本地保存每日新词目标，并明确当日批次不可变。
- Debug 页面保持只读，增加当前日期、每日目标、任务 word_id、第一层/整任务状态及词库进度。
- JSON 导出增加 `vocabularySummary` 和 `dailyNewWordTasks`，不导出完整 5847 词内容。

## 11. 自动化与真机验收

必须执行 `flutter analyze` 和全量 `flutter test`。测试至少覆盖正式 asset 校验、5847 条解析、异常不静默丢弃、同日幂等、重启持久化、词数不足、已学排除、设置冻结、第一层/语境恢复、历史积压、跨月、跨年、首页复习优先、数据库迁移和 JSON 导出。

只有 `adb devices -l` 能识别 Samsung SM-X610 时才执行真机安装与验证；否则验收报告必须明确写“未执行：设备不可用”，不得声称通过。真机测试不得清空数据库或静默删除旧数据。

完成后输出验收报告并停止，不继续开发 FSRS、AI 文章接口、登录、云同步、通知等其他功能。
